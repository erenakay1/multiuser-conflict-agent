## 3. Work done
**Eren:**
- Reviewed the Harness-MU code: authority priority is fixed in code, the LLM only judges compatibility; there is no rule for users with equal authority.
- Prepared the structure of the formal problem definition and a symbol-to-code table.
- Implemented config loading and a common LLM client (local Ollama for development, API for experiments) with structured JSON output and retries.
- Built the event-planning environment: 90 mock venues and a constraint checker that tests whether a plan satisfies a constraint.
- Built a template-based scenario generator and generated the first 50 scenarios. Every label is checked against the environment (conflicting pair has no common plan; all other pairs do).
- Implemented constraint extractor v0 (message → structured constraints) and evaluated it on all 50 scenarios.
**Yusuf:**
- Finalised four conflict types (direct, range, indirect, revision) and the scenario schema.
- Prepared the annotation guideline v1 (type table, environment rules, examples, non-conflict cases).
- Built the labelling tools: a blind browser interface (generator labels hidden) and an agreement script (Cohen's κ).
- Annotated all 50 scenarios (462 message pairs).
**Both:**
- Adjudicated the 9 disagreements between the human and generator labels; decisions and rationales are recorded in the repository.
- Design decisions: under equal authority the hierarchy baseline (S2) asks the users; suggestions such as “How about X?” are treated as soft constraints.

## 6. Problems and evaluation
**Problems:**
- Exam week: H2 work started late and was done together with H3.
- Guideline wording “same topic” was ambiguous: two different activity suggestions were labelled indirect instead of direct (3 pairs).
- 5 of the 6 rule-based indirect conflicts (e.g. 400 TL budget vs fine dining) were not marked in the first pass; the rules were not seen as absolute.
- Suggestions (“How about X?”) are unclear as requirements: the extractor missed 12 such messages and the annotator questioned them too.
- Extractor output format: single values given as lists, different spellings (fine-dining / fine_dining).
- Harness-MU has no equal-authority rule, so our S2 needs its own rule.
**Evaluation:**
We have achieved our goals for h2 and h3; some parts have been partially completed due to dependencies in subsequent steps. We now have a dataset containing the four types of conflicts we defined, with their conflicts known in advance. The detectors will be tested on this data in the next step. How did we know it was correct? Yusuf independently labeled the 50 scenarios without seeing the generator’s labels. The agreement coefficient κ was 0.857. We resolved the remaining 9 discrepancies together. The discrepancies were not random; they stemmed from an ambiguous statement in the guide and rule-based indirect conflicts. Therefore, we will update the guide.
